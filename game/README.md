# 보카로 카드게임 — 플레이 가능한 프로토타입 (v1)

`docs/game-design-foundation.md`(v0.2) 설계를 실제로 구현한 첫 프로토타입입니다.
TypeScript로 게임 로직(엔진)을 짜고, 그 위에 순수 HTML/CSS/DOM으로 화면을
붙였습니다. 지금은 한 화면을 번갈아 보는 **로컬 2인용(Pass & Play)** 형태로
동작하지만, 엔진을 서버로 그대로 옮기면 실시간 멀티플레이로 확장할 수 있도록
설계했습니다 (아래 "멀티플레이 확장 방법" 참고).

## GitHub Pages로 바로 접속하기

`.github/workflows/deploy-pages.yml`이 이 브랜치(및 main)에 푸시될 때마다
자동으로 빌드 후 GitHub Pages에 배포합니다.

> **최초 1회, 저장소 관리자가 직접 해야 하는 설정**이 있습니다 (API로 대신 켤
> 수 있는 권한이 없어 안내만 드립니다): GitHub 저장소의
> **Settings → Pages → Build and deployment → Source**를
> **"GitHub Actions"**로 설정해주세요. 이후에는 푸시할 때마다 자동 배포됩니다.

설정 후에는 저장소의 **Actions** 탭에서 `Deploy game to GitHub Pages` 워크플로가
성공했는지 확인하고, **Settings → Pages**에 표시되는 주소로 접속하면 됩니다.

## 실행 방법 (로컬)

빌드에 별도 패키지 설치가 필요 없습니다 (`tsc`만 있으면 됩니다).

```bash
cd game
tsc -p tsconfig.json     # src/ → dist/ 로 컴파일
npx http-server -p 8080  # 아무 정적 서버나 사용 가능 (file://로 열면 모듈 로딩이 막힐 수 있음)
# 브라우저에서 http://localhost:8080/index.html 접속
```

파일을 고치면 `tsc -p tsconfig.json`을 다시 실행하거나 `tsc -w -p tsconfig.json`으로
watch 모드를 켜두면 됩니다.

## 폴더 구조

```
game/
  src/
    core/               ← 게임 엔진 (DOM에 전혀 의존하지 않는 순수 로직)
      types.ts           타입 정의 (직렬화 가능한 데이터 구조)
      engine.ts           reduce(state, action) 순수 함수 리듀서
      data/
        producers.ts       6명의 보카로P 메타데이터
        stageCards.ts       P카드(무대 카드) 6종 정의
        songCards.ts        곡 카드(스킬 카드) 30장 정의
    ui/                  ← 화면 (DOM 렌더링 + 이벤트 연결)
      render.ts            상태 → HTMLElement 렌더 함수 모음
      cardText.ts          카드 효과를 사람이 읽는 문장으로 변환
      main.ts              엔트리 포인트: 상태 보관 + dispatch + 렌더 루프
  index.html
  style.css
```

## 핵심 설계: 왜 이렇게 나눴는가

`core/`는 **DOM, 브라우저 API, 콘솔 출력 등 부수효과가 전혀 없는 순수 함수**로만
이루어져 있습니다. `reduce(state, action) => newState` 하나가 전부입니다.

이렇게 만든 이유는 문서에서 요청한 "나중에 사이트에서 멀티로 구현"을 염두에 둔
것입니다. 서버-권위(server-authoritative) 방식으로 멀티플레이를 붙이려면:

1. 서버가 `GameState`를 들고 있는다.
2. 클라이언트는 `GameAction`만 서버로 보낸다 (카드 발동, 턴 종료 등).
3. 서버는 받은 액션을 그대로 `reduce(state, action)`에 넣어 새 상태를 계산한다.
4. 서버가 새 상태를 두 클라이언트에 브로드캐스트한다 (또는 각자에게 필요한
   부분만 — 상대 손패 등은 가려서 — 골라 보낸다).
5. 클라이언트는 받은 상태로 `ui/render.ts`를 그대로 재사용해 화면만 그린다.

즉 `core/` 폴더는 지금 이대로 Node.js 서버(예: WebSocket 서버)에 옮겨 심을 수
있습니다. `ui/`만 "로컬 상태를 직접 reduce" 하는 대신 "서버에 액션을 보내고
서버가 보내주는 상태를 그리는" 방식으로 바꾸면 됩니다.

> 다만 지금 손패 공개 처리(`revealedHand`, 모자이크롤 효과)나 랜덤 처리
> (`Math.random()` 기반 버림/셔플)는 로컬 단일 프로세스를 가정한 단순화입니다.
> 실서버로 옮길 때는 (1) 상대에게 보여선 안 되는 정보(상대 손패, 덱 순서)를
> 클라이언트별로 필터링해서 보내고, (2) 셔플/랜덤 버림을 서버 쪽에서만 계산하도록
> 정리가 필요합니다.

## 게임 규칙 요약

- **P카드(무대 카드)**: 게임 시작 시 1장을 골라 테이블 중앙에 공개. 게임이
  끝날 때까지 **양쪽 플레이어 모두**에게 동일하게 적용되는 공용 규칙입니다
  (유희왕 필드 마법 + MTG 플레인체이스 + Fluxx를 참고한 설계 — 자세한 근거는
  `docs/game-design-foundation.md` 참고).
- **곡 카드**: 코스트를 내고 발동하는 스킬 카드. 보컬(공격) / 서포트(버프·디버프)
  / 스토리(설치형 지속효과) / 코러스(상대 턴에도 반응 가능) 4타입.
- **턴 구조**: 인트로(스토리 효과 발동) → 드로우 → 차지(재생 포인트 +1) →
  메인(기본 1곡 발동, 무대에 따라 늘어남) → 상대의 반응(코러스) 구간 → 종료.
- **승리 조건**: 배틀 모드(상대 인기도 0) / 차트 모드(턴 제한 후 인기도 비교).
  덱을 다 써버리면(더 낼 곡이 없으면) 그 시점 인기도 비교로 즉시 승부를 가립니다.
- **무대 시너지**: 발동한 곡의 소속 P가 현재 무대 P카드와 같으면 소소한
  보너스(보컬 데미지 +1 / 서포트 효과 +1)가 붙습니다. 덱 구성 자체는 자유입니다.

## 알려진 한계 (다음 확장 후보)

- 덱빌딩 없음: 지금은 30장 전체를 그대로 각자의 덱으로 사용합니다. 카드 선택형
  덱빌딩 화면은 아직 없습니다.
- AI(1인용) 없음: 지금은 로컬 2인용만 지원합니다.
- 반응(코러스) 판정이 "카드를 낸 직후"가 아니라 "턴 종료 시점"으로 단순화되어
  있습니다 (스택/인터럽트 없이 한 번의 반응 창만 제공).
- 랜덤 처리가 완전히 시드 고정되어 있지 않습니다 (덱 셔플만 시드 가능, 무작위
  버림 등은 `Math.random()` 사용) — 재현 가능한 리플레이가 필요해지면 정리 필요.
